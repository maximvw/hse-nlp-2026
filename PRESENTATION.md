# Текст для рассказа

## Введение

Проект — чат-бот для анализа YouTube-видео на русском языке. Пользователь кидает ссылку на видео, система скачивает аудио, распознаёт речь, определяет спикеров, строит индекс — и после этого можно задавать вопросы: «о чём говорили на 10-й минуте?», «что обсуждали про X?», «сколько спикеров?». Весь NLP-инференс, кроме LLM, выполняется локально.

## Пайплайн обработки

Обработка видео состоит из 5 NLP-этапов, идущих последовательно:

### 1. Voice Activity Detection — Silero VAD

Первый этап — определить, где в аудио есть речь, а где тишина, музыка или шум. Используется **Silero VAD** — компактная модель на PyTorch, загружаемая через `torch.hub`. Она работает на 16kHz mono WAV и возвращает таймстемпы речевых сегментов. Далее близкие сегменты (< 0.5 сек между ними) мержатся, слишком короткие (< 0.3 сек) отбрасываются. После этого сегменты группируются в чанки до 30 секунд — это нужно для эффективной подачи в ASR-модель.

Почему VAD важен: без него Whisper получал бы длинные куски тишины, что замедляет работу и ухудшает качество распознавания.

VAD расшифровывается как Voice Activity Detector, или детектор речевой активности.Если говорить совсем просто, это  фильтр, который в реальном времени понимает: говорит сейчас человек или в микрофоне просто тишина и фоновый шум.
### 2. Automatic Speech Recognition — whisper.cpp (large-v3-turbo-q5_0)

Для транскрибации используется **whisper.cpp** через Python-обёртку `pywhispercpp`. Конкретно — модель **large-v3-turbo** в квантизации **q5_0**. Это C++ реализация OpenAI Whisper, оптимизированная для CPU-инференса, в частности для Apple Silicon.

Ключевые детали:
- Модель получает аудио-чанки, подготовленные VAD-ом (до 30 сек каждый)
- Включены **word-level timestamps** (`token_timestamps=True`) — это позволяет получить время каждого слова, что критично для точного выравнивания с диаризацией
- Поддерживается **параллелизация через ProcessPoolExecutor** — несколько воркеров, каждый со своей копией модели, транскрибируют чанки параллельно
- Квантизация q5_0 даёт хороший баланс между качеством и скоростью на CPU

Временные смещения пересчитываются: Whisper возвращает время относительно начала чанка, а мы прибавляем смещение чанка в исходном аудио.

### 3. Speaker Diarization — WavLM + Agglomerative Clustering

Диаризация — определение «кто говорил когда». Реализована в два шага:

**Шаг 1 — извлечение спикер-эмбеддингов:**

Используется **microsoft/wavlm-base-sv** — модель WavLM с x-vector головой для верификации спикеров. Это не самая крупная модель WavLM, но она специально файнтюнена для задачи speaker verification. Для каждого VAD-сегмента извлекается эмбеддинг — вектор фиксированной размерности, характеризующий голос. Аудио обрезается до 3 секунд (достаточно для идентификации), эмбеддинги L2-нормализуются. Батчированный инференс через HuggingFace `AutoFeatureExtractor` + `WavLMForXVector`.

**Шаг 2 — кластеризация:**

**AgglomerativeClustering** из scikit-learn с **косинусной метрикой** и **average linkage**. Если количество спикеров неизвестно — используется `distance_threshold` (по умолчанию 0.4) для автоматического определения числа кластеров. Если известно — задаётся `n_clusters`.

Важный момент: транскрибация и диаризация запускаются **параллельно** через `ThreadPoolExecutor` — они обе используют один и тот же аудиофайл и VAD-сегменты, но не зависят друг от друга.

**Шаг 3 — выравнивание (alignment):**

После получения транскрипта и спикерных меток их нужно совместить. Для каждого сегмента транскрипции берётся **середина по времени** и находится ближайший спикерный терн. Последовательные сегменты одного спикера склеиваются.

Почему WavLM, а не pyannote: pyannote требует HuggingFace-токен и принятие лицензии, что усложняет деплой. WavLM-SV работает из коробки и переиспользует VAD-сегменты — не нужна дополнительная сегментация.

### 4. Semantic Indexing — sentence-transformers + FAISS

Для семантического поиска по транскрипту строится векторный индекс:

- Модель эмбеддингов: **paraphrase-multilingual-MiniLM-L12-v2** из sentence-transformers. Это мультиязычная модель на базе MiniLM, обученная на парафразах — хорошо подходит для русского языка и семантического сходства
- Транскрипт разбивается на чанки до 1000 символов с метаданными (время, спикеры)
- Индекс строится через **FAISS** (Facebook AI Similarity Search) — библиотеку для быстрого поиска ближайших соседей в пространстве эмбеддингов
- Обёртка — LangChain `FAISS`, которая связывает документы с их векторами

При поиске запрос пользователя эмбеддится той же моделью и находятся top-k ближайших чанков.

### 5. Summarization — LLM через OpenRouter

Три стратегии суммаризации, выбираемые автоматически по длине транскрипта:

- **Single pass** (до ~10 мин, ≤5000 символов) — весь текст в один промпт LLM
- **Rolling merge** (10–30 мин) — последовательная суммаризация: `summary_n = LLM(summary_{n-1} + chunk_n)`. Модель накапливает контекст предыдущих частей
- **Hierarchical** (>30 мин) — каждый чанк суммаризируется независимо, затем финальный запрос объединяет все частичные саммари

LLM-запросы идут через OpenRouter API (OpenAI-совместимый интерфейс), модель по умолчанию — **nvidia/nemotron-nano-9b-v2**.

## Агентная архитектура

Чат-бот построен как **LLM-агент** на LangChain (`create_agent`, LangGraph под капотом). Агент сам решает, какой из 7 инструментов вызвать под конкретный вопрос пользователя. Это не RAG в чистом виде — семантический поиск это лишь один из инструментов. Структурные запросы («сколько спикеров?», «что было на 5-й минуте?») обрабатываются напрямую через индекс без обращения к векторному поиску.

История диалога сохраняется между вопросами — агент помнит контекст разговора.

## Архитектуры моделей под капотом

### Silero VAD

Silero VAD — это лёгкая модель (~2 МБ) на основе **1D depthwise-separable свёрток + LSTM**. Не трансформер.

Как устроена:
- На входе — сырой аудиосигнал (16kHz), нарезанный на фреймы по 512 сэмплов (32 мс)
- Стэк **1D depthwise-separable convolutional** слоёв извлекает локальные акустические признаки из каждого фрейма. Depthwise-separable свёртки — это трюк из MobileNet: сначала свёртка по каждому каналу отдельно (depthwise), потом pointwise 1×1 свёртка для смешивания каналов. Это радикально уменьшает число параметров по сравнению с обычными свёртками
- Далее **LSTM-слой** моделирует временные зависимости между фреймами — нужно, чтобы модель учитывала контекст (например, пауза внутри слова ≠ тишина между фразами)
- На выходе — вероятность `[0, 1]` для каждого фрейма: речь или не речь

Почему такая архитектура: VAD должен быть быстрым и маленьким, он работает как предобработка перед тяжёлыми моделями. Трансформер здесь — overkill. Связка CNN+LSTM — классический и проверенный подход для потокового аудио.

### Whisper (large-v3-turbo)

Whisper — это **encoder-decoder Transformer** для ASR, обученный OpenAI на 680 000 часов размеченного аудио с вебa (weakly-supervised).

**Encoder** (обрабатывает аудио):
- Вход: аудио → **80-канальная log-mel спектрограмма** (окно 25 мс, шаг 10 мс)
- 2 слоя **1D свёрток** (kernel size 3, stride 2) — снижают временное разрешение в 4 раза и проецируют mel-фичи в пространство модели (1280 dim для large)
- Далее **синусоидальное позиционное кодирование** + стэк из **32 Transformer encoder блоков** (self-attention + FFN)
- На выходе — последовательность скрытых состояний, представляющих акустический контекст

**Decoder** (генерирует текст):
- Стандартный авторегрессионный Transformer decoder: **cross-attention** к выходам энкодера + **masked self-attention**
- Генерирует токены последовательно (BPE-токенизация, словарь ~51k)
- Специальные токены управляют поведением: `<|ru|>` задаёт язык, `<|transcribe|>` — режим транскрибации, `<|notimestamps|>` или таймстемп-токены

**large-v3-turbo** — дистиллированная версия large-v3:
- Энкодер остаётся тем же (32 слоя, 1280 dim) — он отвечает за качество понимания аудио
- Декодер ужат с **32 до 4 слоёв** через knowledge distillation — ученик обучается воспроизводить выходы учителя (полного large-v3)
- Результат: скорость инференса вырастает в ~4–5 раз, качество теряется минимально (WER деградирует на ~1-2%)

**Квантизация q5_0**: веса модели хранятся в 5 битах вместо 16 (fp16). Это уменьшает размер модели и ускоряет CPU-инференс за счёт меньшего давления на память, с минимальной потерей качества.

### WavLM-base-sv

WavLM — это **Transformer encoder** для обработки речи, разработанный Microsoft. Архитектурно наследует **HuBERT** (Hidden-Unit BERT).

**Backbone (WavLM-base):**
- Вход: сырой аудиосигнал (16kHz)
- **CNN feature encoder**: 7 слоёв 1D свёрток (512 каналов, kernel sizes от 10 до 2, strides от 5 до 2) — преобразуют waveform в последовательность фреймов (~50 фреймов/сек, 512 dim)
- **12 Transformer encoder блоков** (768 dim, 12 голов attention)
- Ключевое отличие от HuBERT: **gated relative position bias** в attention — вместо абсолютного позиционного кодирования используется обучаемое относительное смещение с гейтингом. Это лучше обобщается на разные длины аудио

**Предобучение** (self-supervised):
- **Masked speech prediction** (как в HuBERT/BERT): случайные спаны аудио маскируются, модель предсказывает дискретные псевдометки (полученные через кластеризацию k-means на фичах предыдущей итерации)
- **Denoising**: при обучении к аудио подмешивается шум и другие голоса — модель учится быть робастной к помехам. Это главная фишка WavLM по сравнению с HuBERT

**Speaker verification head (x-vector):**
- Поверх выходов Transformer энкодера добавляется голова для извлечения спикер-эмбеддингов
- **Statistics pooling**: по всем фреймам считается mean и std, конкатенируются → вектор фиксированной длины
- Далее **линейные слои** проецируют в пространство эмбеддингов (512 dim)
- Файнтюнинг на задаче speaker verification (VoxCeleb): модель учится, чтобы эмбеддинги одного спикера были близки, а разных — далеки

В нашем проекте мы берём эти 512-мерные эмбеддинги и кластеризуем их через AgglomerativeClustering — получаем метки спикеров.

### paraphrase-multilingual-MiniLM-L12-v2

Это **Transformer encoder** из семейства sentence-transformers, оптимизированный для получения sentence embeddings.

**Базовая архитектура (MiniLM):**
- **12 Transformer encoder слоёв**, 384 hidden dim, 12 голов attention
- MiniLM получен через **knowledge distillation** из большой модели: ключевая идея — ученик обучается воспроизводить **self-attention распределения** последнего слоя учителя (а не просто логиты). Это позволяет маленькой модели сохранить «понимание» отношений между токенами

**Мультиязычность:**
- Базовая модель сначала обучена на английском
- Затем применяется **multilingual knowledge distillation**: берётся параллельный корпус (одно и то же предложение на 50+ языках), и мультиязычная модель-ученик обучается давать одинаковые эмбеддинги для переводных пар. Учитель — английская sentence-transformers модель
- Результат: предложения на разных языках с одинаковым смыслом попадают в близкие точки пространства

**Как получается sentence embedding:**
- Текст токенизируется, прогоняется через 12 слоёв Transformer
- На выходе — **mean pooling** по всем токенам (усреднение скрытых состояний)
- Полученный 384-мерный вектор и есть эмбеддинг предложения

В нашем проекте чанки транскрипта и поисковые запросы эмбеддятся этой моделью, а FAISS ищет ближайших соседей по L2/cosine distance.

### Nemotron-nano-9b (LLM)

**Decoder-only Transformer** от NVIDIA на 9 миллиардов параметров.

- Архитектура: стандартный causal (autoregressive) Transformer decoder — только masked self-attention, без энкодера
- **Grouped Query Attention (GQA)**: вместо отдельных key/value голов для каждой query головы, несколько query голов разделяют одну пару key/value. Снижает потребление памяти при инференсе (меньше KV-cache)
- **RoPE (Rotary Position Embeddings)**: позиционное кодирование через вращение в комплексном пространстве — лучше экстраполирует на длинные контексты, чем абсолютные позиции
- **SwiGLU activation** в FFN-слоях: `SwiGLU(x) = Swish(xW₁) ⊙ (xW₂)` — gated variant, даёт лучшее качество, чем ReLU/GELU при том же числе параметров

В нашем проекте LLM используется для двух задач: суммаризация транскрипта и работа агента (tool calling — выбор инструментов и генерация ответов).
